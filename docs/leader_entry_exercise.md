# Leader 入场练习

这份练习必须由 Leader 亲自完成，Codex 可以逐步提示，但不能代替验收。

## 练习 A：修改已有卡牌

目标：证明 Leader 知道卡牌内容在哪里。

1. 打开 `src/game/cards.ts`。
2. 找到“有据主张”。
3. 修改它的名称、`description` 和 `baseDamage`。
4. 运行 `npm.cmd test` 和 `npm.cmd run build`。
5. 用 `git diff` 查看自己改了什么。
6. 恢复原值并再次运行测试。

通过标准：Leader 能指出只修改了 `src/game/cards.ts`，并能用自己的话解释名称、描述和数值各控制什么。

## 练习 B：增加第七张卡

目标：证明 Leader 能沿用现有数据结构增加内容。

1. 从 `main` 创建自己的练习分支。
2. 在 `CARD_IDS` 中加入一个新的英文 ID。
3. 在 `CARDS` 中加入同 ID 的完整卡牌定义。
4. 运行测试和构建，确认新卡可以进入随机卡池。
5. 用自己的 Git 身份提交。
6. 说明为什么只需要修改卡牌数据文件。
7. 切回 `main`，确认正式基准仍为 6 张卡。

Codex 演示分支：`exercise/seventh-card-demo`。该分支仅用于查看范例，不能作为 Leader 自己通过 Test 2 的证据。

## 练习 C：Git 回退与恢复

目标：证明 Leader 能安全处理错误修改。

1. 在自己的练习分支修改一个卡牌数值。
2. 用 `git diff` 查看修改。
3. 创建一次练习提交。
4. 回退到修改前状态。
5. 再恢复该提交。
6. 切回 `main`，确认正式版本没有被破坏。

通过标准：Leader 能说明当前分支、当前版本以及回退和恢复分别发生了什么。
